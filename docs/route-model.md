# 福田地面道路积水绕行模型

[打开福华一路示例](https://shallowpromise.github.io/smartcity/?view=routes)。在「9·7 复盘」第 240 分钟，从中心四路与福华一路交叉口到彩田路与福华路交叉口，常规线长 1,195.5 m，沿线模型最高水深 49 cm。以 15 cm 为排除阈值，替代线长 1,250.5 m，最高 2 cm。两线从同一节点出发，到达同一节点。红色实线标出常规线上超阈值的区段，水深标签定位在最高值所在位置。

研究边界为东经 114.040–114.100、北纬 22.533–22.572。投影沿用底图，西北角为原点，x 向东、z 向南，单位米。网格按北到南、西到东的行优先顺序编码。现有深度字节值 0 表示模型输出 0 cm，255 表示至少 255 cm。输出的网格最高水深不等同于路面实测积水。

## 计算和覆盖说明

1. 路网节点编号一致才连通。每条有向路段以 OSM way、起节点和终节点标识。道路相交但未共享节点时不可转向。
2. 用上一条路段作为 Dijkstra 的状态，按米累计几何长度。在路口检查禁转或唯一允许转向，并禁止原路立即折返。先求常规最短路，再排除水深达到阈值的路段，求当前约束下的最短路。
3. 路段在每条网格边界处分割，检查各区间与两个端点；地图只在实际超阈的区间画红线。每次更换时间、情景、阈值或起终点均使用对应数据重算。
4. 44 条限制中有 13 条成员不完整。能定位的 7 个途经节点保守排除相关转向；另有 7 条完整关系没有生成额外的地面图约束。具体关系编号和处理结果可在路网的 `coverage` 字段复核。汇总后图中有 38 组禁用的连续路段组合。部分未匹配限制可能落在范围外或不在本模型覆盖的道路上。
5. 常规路网不通、当前水深断路、水深资料不足及起终点相同分别报告。无水深值的路段不能进入避水路线。当前为单帧地面机动车情景模型，未接入实时封控、桥面及隧道内实测水深，也未预测行车过程中未来时刻的积水变化。

## 场所接驳

在设施名录中手动选择避难场所或地铁出入口，点击“比较接驳路线”。可接驳的参考点在模型范围内，且距最近地面道路节点不超过 120 m。页面列出这段距离，所画路线止于机动车道上的节点。

“最短避水路线”按几何距离求解。“低水深优先”的路段代价为长度乘以 `1 + 3 × (路段最大水深 / 排除水深)²`，再乘以道路等级系数。主干道、次干道、三级路、未分类道路、住宅街道、生活街道的系数依次为 1、1.02、1.04、1.06、1.08、1.12，是本模型的路径偏好参数。两种路线均排除达到阈值和缺测的路段，并遵循相同交通限制。界面显示实际路线长度。若全部路径因已知水深断开，结果代码为 `no_safe_route`。

## 复现与验收

在发布仓库根目录运行以下命令即可复算示例。输出 JSON 含有序路段编号、常规线与替代线里程、沿线峰值及积水位置。

```sh
node scripts/solve-route.mjs 7959603173 8516154909 replay-2309 240 15
node --test system/tests/*.test.mjs
```

公开数据文件 `system/public/data/road-network.json` 含有节点、道路名称表、有向边、穿越网格编号、禁转组合和覆盖记录。`scripts/traffic-controls.json` 是本次使用的交通控制输入快照。可用上游模型仓库对应版本的 `data/raw/osm_raw.json` 重建路网。

```sh
python3 scripts/build-road-network.py /path/to/osm_raw.json
```

验收覆盖两种不同的起终点、相同起终点、不可达、准确命中阈值、缺测、禁转、单行、手机选点和全情景逐帧计算。道路资料及其派生路网按 ODbL 1.0 提供。[OpenStreetMap 署名与许可](https://www.openstreetmap.org/copyright)
